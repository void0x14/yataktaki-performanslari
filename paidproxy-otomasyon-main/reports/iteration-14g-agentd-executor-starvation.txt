Source mapping
--------------
services/agentd/supervisor.py currently creates three long-lived tasks per
worker at the worker start boundary:
  _read_worker_stream(... stdout)
  _read_worker_stream(... stderr)
  _watch_process(handle)

The stream reader uses asyncio.to_thread(stream.readline).
The process watcher uses asyncio.to_thread(handle.process.wait).
The display path uses asyncio.to_thread(select_display_agent, ...).

This explains the observed boundary: agentd records command_received, but the
display handler's default-executor work cannot start while the default pool is
occupied by persistent worker pipe/read and wait jobs.
